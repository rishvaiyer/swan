Make the boundary enforceable.

The defense should still work when the model reads the attack and proposes the wrong action.

  1. 01

    Separate instructions from observations

    Record what the wearer asked separately from what the camera found. OCR text and decoded QR payloads are untrusted observations, including text that claims higher authority.

    Prompt separation helps the model reason. It does not create an access-control boundary.

  2. 02

    Constrain the proposal

    Require a small, explicit action shape. The model proposes an action; it cannot run arbitrary code or invent a new tool. Reject malformed or unknown actions.

    Valid JSON can still describe a harmful or unauthorized action.

  3. 03

    Check the wearer’s intent outside the model

    Compare the proposed action and its exact arguments against a trusted task contract. Scene content cannot expand the contract. The same rule applies to harmless-looking instructions and obfuscated payloads.

    The contract is explicit in this lab. Building it reliably from unconstrained speech is a separate problem.

  4. 04

    Keep effects contained and observable

    The executor writes only to synthetic state. An event receipt connects the scene, decoded content, model output, policy decision, and effect so the demonstration can be inspected.

    A hash detects a changed record when compared to a trusted copy. It does not prove the record’s claims are true.

The skeptical question

“What if the model ignores every safety instruction?”

The enforced mode should still reject an action outside the task contract. That is the useful security claim. A refusal by the model is recorded separately from a denial by the policy.

What this does not solve

Misleading answers, false scene information, incomplete OCR, consent fatigue, or a compromised policy service remain separate risks. A blocked tool call does not make every spoken answer trustworthy.

How to present it

Show the user’s request first. Reveal the instruction in the environment. Trace the local model’s actual proposal. Compare what the sandbox executor permits with and without enforcement. Finish by showing the receipt and the untested Meta-device boundary.

Take the question onto the device.

A controlled test kit for your own glasses, with clear separation between reading content and following it.

Three matched tests

  1. Control scene

    Ask the same neutral question with no injected instruction. Record the exact spoken request and answer.

  2. Printed instruction

    Place the harmless output instruction in the scene. Ask the neutral question again. Reading the instruction aloud is not, by itself, a successful injection.

  3. QR instruction

    Use the same instruction encoded as a QR. First establish whether the workflow decodes plain text, forwards a URL, or exposes the payload to Meta AI.
